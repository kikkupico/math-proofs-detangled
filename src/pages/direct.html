Most theorems have the form “if P, then Q”. The most natural way to prove one: assume P is true, then use it, together with definitions and known facts, to show Q must be true too.

Suppose P. … unpack definitions … … use what you know … Therefore Q. Thus P → Q. ∎

Givens gain P. The goal shrinks from P → Q to just Q.

Example 1

If n is even, then n² is even

Watch the givens, the goal and the written proof change together.

Start: no givens except that n is an integer. The goal is an if–then.

The goal has the form P → Q. So assume P: it moves to the givens, and the goal becomes Q.

Unpack the definition. “Even” means “equals 2 times some integer”. So we can name that integer k.

Now the goal, unpacked, asks for n² = 2 × (some integer). Compute n² and look for a factor of 2.

n² = 2(2k²) and 2k² is an integer. Goal reached. That's the whole proof.

Givens

  • n ∈ ℤ
  • n is even
  • n = 2k, k ∈ ℤ

Goal

  • n even → n² even
  • n² is even
  • n² = 2j for some j ∈ ℤ
  • n² = 2j for some j ∈ ℤ
Suppose n is even. Then n = 2k for some integer k. So n² = (2k)² = 4k² = 2(2k²). Since 2k² is an integer, n² is even. ∎
Example 2

If 0 < a < b, then a² < b²

Here there's no definition to unpack. Instead, you use known facts about inequalities: multiplying both sides by a positive number keeps the direction.

The trick is to work backwards in scratch work: “I want a² < b². I'd get a² < ab by multiplying a < b by a, and ab < b² by multiplying by b.” Then write the proof forwards.

Assume the hypothesis.

Multiply a < b by a, which is positive.

Multiply a < b by b, also positive (since b > a > 0).

Chain the two inequalities.

Suppose 0 < a < b. Multiplying a < b by the positive number a gives a² < ab. Multiplying a < b by the positive number b gives ab < b². So a² < ab < b², and therefore a² < b². ∎
Two kinds of writing

Scratch work versus the final proof

Scratch work

Where you think

List givens and goal. Unpack definitions. Work backwards from the goal. Try things that fail. None of this has to be tidy, and none of it goes in the final proof.

Final proof

What you hand in

Only the steps that justify the conclusion, in order, in full sentences. It explains why the theorem is true, not how you found the argument.

Common slip

Starting from the conclusion. “Suppose a² < b² … so a < b” proves the converse, not the theorem. Working backwards is great in scratch work; the written proof must run forwards from the hypothesis.
